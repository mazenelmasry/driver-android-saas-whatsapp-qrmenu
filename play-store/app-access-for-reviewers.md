# الوصول للمراجعين (App access) — كيف يمنح المالك مراجع Google حساباً يعمل

Google يتطلّب حساباً حقيقياً وقابلاً للاستخدام يستطيع مراجعوهم الدخول به بلا تفاعل بشرى من طرفك (لن يتصلوا بك لطلب رمز OTP حقيقى). الحل القياسى: **رقم هاتف اختبارى فى Firebase** له رمز ثابت، مربوط بحساب سائق تجريبى فى قاعدة البيانات.

## الخطوات (المالك ينفّذها، خارج نطاق هذا الوكيل)

### 1) رقم اختبارى فى Firebase (لكل مشروع Firebase — منيورا وتاج إن كانا منفصلين)
1. Firebase Console ← Authentication ← Sign-in method ← Phone ← **Phone numbers for testing**.
2. أضِف رقماً وهمياً (مثال: `+966500000001`) ورمزاً ثابتاً (مثال: `123456`) — Firebase لا يرسل SMS حقيقياً لهذا الرقم ولا يستهلك حصّة SMS.
3. كرّر لكل نكهة على مشروعها الخاص إن كانت مشاريع Firebase منفصلة (تحقّق من `google-services.json` فى كل من `app/src/meniura` و`app/src/taaj` — إن كان معرّف المشروع مختلفاً فهما منفصلان).

### 2) حساب سائق تجريبى مربوط بمطعم تجريبى (فى الباك اند)
من لوحة الشركة (`/co`) لأى شركة تجريبية (أو أنشئ شركة تجريبية جديدة إن لم توجد):
1. **إدارة السائقين** (`Company\Resources\DeliveryDrivers`) ← أضِف سائقاً برقم الهاتف الاختبارى نفسه من الخطوة 1 (بنفس صيغة E.164، مثال `+966500000001`).
2. أرسل له **دعوة** (`InviteDriverAction`) — الدعوة تربطه بهذا المطعم/الفرع.
3. سجّل الدخول فى التطبيق برقم الهاتف الاختبارى + الرمز الثابت (`123456`) → سيُطلب منه دعوة/كلمة مرور أول مرة — عبّئها بقيمة معروفة للمراجع (مثال: `Review2024!`) واكتبها فى ملاحظات Play Console.

### 3) طلب توصيل تجريبى جاهز للظهور
لكى يرى المراجع تدفّق "قبول عرض ← استلام ← تسليم" فعلياً بلا انتظار طلب حقيقى:
1. من لوحة الكاشير/الطلبات فى نفس الشركة التجريبية، أنشئ طلب توصيل (dine_in/delivery حسب إعداد الفرع) واربطه بفرع قريب من الموقع الذى سيستخدمه المراجع (أو اترك التطبيق فى وضع "متاح" وأنشئ الطلب لحظة المراجعة — الأسهل عملياً هو تجهيزه **قبل** بدء المراجعة وتفعيل "متاح" فى التطبيق التجريبى بحيث يصل العرض للمراجع خلال ثوانٍ من فتح التطبيق).
2. بديل أبسط لا يعتمد على توقيت: أرفق فى ملاحظات المراجعة تعليمات نصية توضح أن "متاح" لا يُظهر عروضاً إلا عند وجود طلب توصيل نشط فى النظام، وأن هذا سلوك متوقّع بتصميم التطبيق (بدعوة فقط، لا عروض وهمية دائمة) — واذكر أنك جهّزت حساباً وسأرفق فيديو/لقطات توضّح التدفّق الكامل (نفس فيديو `permissions-declarations.md`).

### 4) ما تكتبه فى حقل "App access" بـPlay Console
```
This app is invite-only for delivery drivers linked to a restaurant.
Test credentials:
  Phone: +966500000001 (Firebase test number — instant sign-in code 123456)
  If a password is requested on first login, use: Review2024!
The reviewer can sign in directly with the code above; no real SMS is sent
and no human interaction is required on our side.
A test delivery order is available in the connected demo restaurant's
account so the reviewer can see the "go available → receive offer → accept
→ pick up → deliver" flow. See the attached demo video for the full flow
including the background location prominent disclosure screen.
```
(اكتبها بالإنجليزية — حقل Google موجَّه لمراجعين دوليين).

### 5) تذكير أمنى
- لا تستخدم رقماً/كلمة مرور مرتبطة بحساب مطعم أو سائق حقيقى — أنشئ شركة تجريبية معزولة.
- بعد انتهاء المراجعة الأولى يمكنك ترك الرقم الاختبارى مفعّلاً (Firebase test numbers لا تُستهلَك ولا تنتهى) لتسهيل أى مراجعة مستقبلية (تحديثات التطبيق تُعاد مراجعتها أحياناً).
